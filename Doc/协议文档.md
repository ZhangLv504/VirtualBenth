# 通信协议设计

VirtualBench 设备模拟器（device_simulator）与上位机（host_gui）之间的自定义二进制应用层协议。

> 本文档是双端之间的**契约**：不看代码，照着本文即可独立实现另一端。

---

## 1. 目的与范围

**做什么**

- 规定 device 与 host 之间在 TCP 长连接上的帧格式、命令语义与解析规则。
- 覆盖设备启停控制、采样数据上报、状态与错误通知。

**明确不做（边界）**

- 不加密、不压缩。
- 不提供重传 / 可靠交付，可靠性依赖 TCP。
- 不做应用层分片重组（单帧 payload 不超过 64KB）。
- 不做跨机时钟同步（`ts` 为设备本地单调时钟，只用于表示相对先后顺序）。
- 不做应用层背压（接收端处理不过来由 host 侧环形缓冲削峰，协议层不限流）。

---

## 2. 术语与约定

| 约定 | 内容 |
| --- | --- |
| 字节序 | **全部多字节字段一律小端（Little-Endian）** |
| 字段类型 | `uint8` / `uint16` / `uint32` / `uint64` 均无符号；浮点为 IEEE-754 `float32` |
| 字符串 | UTF-8，不带结尾 `\0` |
| 单位 | 采样率 Hz；时间戳 μs（微秒） |
| 连接角色 | device 为服务端（`listen`），host 为客户端（主动 `connect`），TCP 长连接 |

---

## 3. 帧格式

```
+----------+--------+--------+---------------+-------------+----------+
| magic 2B | ver 1B | cmd 1B | payload_len 2B| payload NB  | crc16 2B |
| A5 5A    | 0x01   |        | (小端)        |             | (小端)   |
+----------+--------+--------+---------------+-------------+----------+
                \_______________ CRC 校验覆盖范围 _______________/
                （ver、cmd、payload_len、payload，不含 magic 与 crc16 本身）
```

### 字段说明

| 字段 | 偏移 | 长度 | 类型 | 含义与取值 |
| --- | --- | --- | --- | --- |
| `magic` | 0 | 2B | — | 固定 `0xA5 0x5A`，帧起始同步字 |
| `ver` | 2 | 1B | uint8 | 协议版本号，当前固定 `0x01` |
| `cmd` | 3 | 1B | uint8 | 命令字，取值见第 4 节 |
| `payload_len` | 4 | 2B | uint16 | **payload 的字节数**（不含帧头与 CRC），合法范围 `0 ~ 65535` |
| `payload` | 6 | NB | — | 命令载荷，结构由 `cmd` 决定，长度 = `payload_len` |
| `crc16` | 6+N | 2B | uint16 | CRC 校验值，低字节在前 |

**要点**

- `payload_len` 的语义是 **payload 长度，不是整帧长度**。整帧长度 = `6 + payload_len + 2`。
- CRC 采用 **CRC16-Modbus**：多项式 `0x8005`（反射实现为 `0xA001`），初值 `0xFFFF`，无最终异或，按字节表驱动计算。
- CRC **覆盖 `ver` ~ `payload` 共 `4 + payload_len` 个字节**，不覆盖 `magic` 与 `crc16`。这是两端最容易写不一致的地方，务必对齐。

## 4. 命令表

| cmd | 名称 | 方向 | payload | 说明 |
| --- | --- | --- | --- | --- |
| 0x01 | HELLO | host→dev | 空 | 版本协商，版本取帧头 `ver` |
| 0x02 | START | host→dev | 采样率(4B) + 通道mask(1B) | 启动采样 |
| 0x03 | STOP | host→dev | 空 | 停止采样 |
| 0x04 | DATA | dev→host | 见 5.1 | 采样数据上报 |
| 0x05 | STATUS | dev→host | 设备状态码(1B) | 状态通知 |
| 0x7F | ERROR | dev→host | 错误码(2B) + 描述 | 错误通知 |
| 0x06–0x0F | — | — | — | 预留（如后续心跳 PING/PONG） |
| 0x10–0x7E | — | — | — | 预留 |

## 5. 命令 payload 逐字节定义

### 5.1 DATA（0x04，dev→host）

| 字段 | 长度 | 类型 | 含义 |
| --- | --- | --- | --- |
| `chanId` | 1B | uint8 | 通道号（0/1/2…） |
| `seq` | 4B | uint32 | 序列号，见下方说明 |
| `ts` | 8B | uint64 | 本批样本起始时间，设备本地单调时钟，单位 μs |
| `cnt` | 2B | uint16 | 本帧样本个数 |
| `samples` | 4B×cnt | float32[] | 采样数据 |

- **一帧只承载一个通道**，多通道数据由设备交错发送多帧。
- **`seq` 按通道独立递增**：每个 `chanId` 各自维护一个计数器，从 0 开始，每发一帧 +1，`uint32` 回绕视为正常。检测丢帧时用模运算：`丢失数 = (cur - last) mod 2^32 - 1`。
- 由于 `payload_len` 上限 65535，而 DATA 头固定 15B，故 **`cnt` 最大约 16379**（每帧）。

### 5.2 START（0x02，host→dev）

| 字段 | 长度 | 类型 | 含义 |
| --- | --- | --- | --- |
| `sample_rate` | 4B | uint32 | 采样率，单位 Hz，必须 > 0 |
| `chan_mask` | 1B | uint8 | 通道使能位掩码，bit0=通道0…，必须 ≠ 0 |

设备收到后回 `STATUS(RUNNING)`；参数非法则回 `ERROR(BAD_PARAM)`。

### 5.3 STOP（0x03，host→dev）

payload 为空（`payload_len = 0`）。设备停止推流并回 `STATUS(IDLE)`。

### 5.4 HELLO（0x01，host→dev）

payload 为空，版本以帧头 `ver` 表达。设备比对成功回 `STATUS(READY)`，不一致回 `ERROR(VER_MISMATCH)`。

### 5.5 STATUS（0x05，dev→host）

| 字段 | 长度 | 类型 | 含义 |
| --- | --- | --- | --- |
| `state` | 1B | uint8 | 设备状态，取值见第 6 节 |

### 5.6 ERROR（0x7F，dev→host）

| 字段 | 长度 | 类型 | 含义 |
| --- | --- | --- | --- |
| `code` | 2B | uint16 | 错误码，见第 6 节 |
| `msg` | N−2 | UTF-8 | 人类可读的描述，长度由 `payload_len` 决定，可为空 |

## 6. 状态码与错误码

### 状态码（STATUS.state）

| 值 | 名称 | 含义 |
| --- | --- | --- |
| 0x00 | IDLE | 空闲，未采样 |
| 0x01 | READY | HELLO 成功，待命 |
| 0x02 | RUNNING | 采集中，持续推送 DATA |
| 0x03 | FAULT | 设备故障 |

### 错误码（ERROR.code）

| 值 | 名称 | 触发场景 | 连接处置 |
| --- | --- | --- | --- |
| 0x0001 | UNKNOWN_CMD | 收到未定义的 cmd | 不关闭 |
| 0x0002 | VER_MISMATCH | 协议版本不一致 | **关闭连接** |
| 0x0003 | BAD_PARAM | 参数非法（采样率=0、mask=0 等） | 不关闭 |
| 0x0004 | BAD_STATE | 状态非法（如未启动就 STOP） | 不关闭 |
| 0x0005 | INTERNAL | 设备内部错误 | **关闭连接** |

- 接收方对**未知的错误码**应忽略，不得崩溃。

## 7. 会话流程

```
host                                   device
  |  --TCP connect ------------------->  |
  |  --HELLO (ver=0x01) -------------->  |
  |  <-------------- STATUS(READY) -----|   版本不符则 ERROR(VER_MISMATCH) 并关闭
  |  --START(rate, mask) ------------->  |
  |  <-------------- STATUS(RUNNING) ---|
  |  <-------------- DATA × N ----------|   持续推流
  |  --STOP -------------------------->  |
  |  <-------------- STATUS(IDLE) ------|
  |  ...可再次 START 复用连接...         |
```

- device 只有在收到 `START` 并回 `RUNNING` 后才开始推送 `DATA`。
- 连接保活：应用层暂不定义心跳，依赖 TCP keep-alive；后续如需可启用预留命令 `0x06/0x07`（PING/PONG）。

## 8. 解析规则（粘包 / 半包）

TCP 是字节流，帧在到达时可能被任意切割或粘连。接收端必须用状态机处理：

1. **找 magic**：在缓冲区中查找 `A5 5A`。若找到位置 `> 0`，先丢弃其前面的脏字节；若找不到，保留最后 1 字节（可能是半个 magic），其余丢弃，等待更多数据。
2. **读帧头**：缓冲区不足 6 字节则等待；否则读出 `payload_len`，计算 `frame_len = 6 + payload_len + 2`。
3. **收整帧**：缓冲区不足 `frame_len` 则等待；否则校验 CRC（覆盖 `ver`~`payload`）。
4. **校验失败**：从 magic 位置**滑动 1 字节**，回到第 1 步重新同步（这样即使 payload 中恰好出现 `A5 5A` 也能恢复）。
5. **校验成功**：分发该帧，消费 `frame_len` 字节，回到第 1 步。

伪代码：

```text
loop:
    pos = find(buffer, [0xA5, 0x5A])
    if pos < 0:
        if len(buffer) >= 1: buffer.drop(len(buffer) - 1)   # 保留最后1字节
        return                                              # 等更多数据
    if pos > 0: buffer.drop(pos)                            # 丢弃magic前脏字节
    if len(buffer) < 6: return                              # 头部未齐
    payload_len = le16(buffer[4:6])
    frame_len = 6 + payload_len + 2
    if len(buffer) < frame_len: return                      # 整帧未齐
    if crc16_modbus(buffer[2 : 6 + payload_len]) != le16(buffer[6 + payload_len : 8 + payload_len]):
        buffer.drop(1)                                      # 重同步
        continue
    dispatch(buffer[0:frame_len])
    buffer.drop(frame_len)
```

## 9. 示例帧（十六进制，可直接作为测试向量）

统一约定：`ver = 0x01`，字节序小端。

### 9.1 HELLO：host→dev，payload 空

```text
A5 5A 01 01 00 00 50 18
^magic ^ver ^cmd ^len=0 ^crc
```

### 9.2 START：采样率 10000Hz，通道 mask = 0x07

```text
A5 5A 01 02 05 00 10 27 00 00 07 59 0C
            ^len=5  ^rate=10000   ^mask
```

### 9.3 STOP：payload 空

```text
A5 5A 01 03 00 00 F1 D8
```

### 9.4 DATA：chanId=0, seq=1024, ts=1712345678000μs, cnt=3, samples=[1.5, -0.2, 0.8]

```text
A5 5A 01 04 1B 00 | 00 | 00 04 00 00 | B0 80 C1 AF 8E 01 00 00 | 03 00 | 00 00 C0 3F | CD CC 4C BE | CD CC 4C 3F | D4 C2
^magic   ^len=27   ^chan   ^seq=1024     ^ts(小端)                  ^cnt=3    ^1.5          ^-0.2          ^0.8      ^crc
```

### 9.5 STATUS：state = RUNNING

```text
A5 5A 01 05 01 00 02 C9 0D
```

### 9.6 ERROR：code = 0x0002，msg = "version mismatch"

```text
A5 5A 01 7F 12 00 | 02 00 | 76 65 72 73 69 6F 6E 20 6D 69 73 6D 61 74 63 68 | 99 AC
^magic   ^len=18   ^code   ^"version mismatch"(UTF-8)                          ^crc
```

## 10. 边界用例（单测清单）

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 空 payload | STOP 帧 | 正常解析，`payload_len = 0` |
| 半帧 | 只到达帧头 | 不解析，保留缓冲等待 |
| 逐字节分片 | 一次喂 1 字节 | 最终仍解析出完整帧 |
| 粘两帧 | 两帧连续到达 | 依次解析出两帧 |
| magic 混入 payload | payload 中含 `A5 5A` | 不误判，靠 CRC 校验重同步 |
| CRC 错误 | 篡改任意 1 字节 | 丢弃该帧，并能重同步到下一帧 |
| 脏数据前缀 | 随机字节 + 正常帧 | 跳过脏字节后解析出正常帧 |
| 截断 magic | 流末尾仅 `A5` | 不误判，保留等待 |
| 未知 cmd | `cmd = 0x55` | 回 `ERROR(UNKNOWN_CMD)`，不崩溃 |
| 最大 payload | `payload_len = 65535` | 正常解析（约 64KB 缓冲） |

## 11. 版本与扩展规则

- 当前协议版本 `ver = 0x01`；收到无法处理的版本应回 `ERROR(VER_MISMATCH)` 并关闭。
- **未知 cmd 必须可被安全忽略**：接收方最多回一次 `ERROR(UNKNOWN_CMD)`，不得崩溃或关闭连接。
- 新增能力一律通过**新增 cmd** 实现，**不得改动现有帧头布局**。
- 若需给已有 cmd 追加字段，接收方按 `payload_len` 截断处理，多余字节忽略（前向兼容）。
- `0x06–0x0F`、`0x10–0x7E` 为预留命令空间。
