### 1.3 通信协议设计（第一个交付物）

帧格式（小端）：

```
+------------+---------+---------+-------------+------------+----------+
| magic 2B   | ver 1B  | cmd 1B  | payload_len | payload NB | crc16 2B |
| 0xA5 0x5A  | 0x01    |         | 2B          |            |          |
+------------+---------+---------+-------------+------------+----------+
CRC16-Modbus 查表法，覆盖 ver ~ payload 全部字段
```

命令表：

| cmd | 名称 | 方向 | payload 说明 |
|---|---|---|---|
| 0x01 | HELLO | host→dev | 版本协商 |
| 0x02 | START | host→dev | 采样率(4B) + 通道mask(1B) |
| 0x03 | STOP | host→dev | - |
| 0x04 | DATA | dev→host | chanId(1B) + seq(4B) + ts(8B) + cnt(2B) + float32样本×cnt |
| 0x05 | STATUS | dev→host | 设备状态码 |
| 0x7F | ERROR | dev→host | 错误码 + 描述 |

粘包/半包处理：接收缓冲区循环执行"找magic → 校验len → 收满整帧 → 校验CRC → 分发"，字节不足则保留等待。

**ONNX模块技术要点**（W7执行时的设计约束）：

- 模型选型：1D-CNN或小型自编码器即可（输入滑窗如128点×多通道，输出异常分数），**不要**上Transformer——面试官问模型细节时要能讲清

- 数值一致性验证：同一组输入Python/C++各推理一次，结果对齐到1e-5——这个坑本身是面试素材
- 量化检测延迟：从样本到达到异常分数输出的端到端延迟，写成简历数字

### 1.6 面试深挖故事（提前写成文稿，每个能讲5分钟）

1. **UI卡死问题**：10kHz数据直接触发重绘导致UI卡死 → 改为环形缓冲削峰 + QTimer 33ms合批提交 + 曲线整段setData替换，CPU从不可用降到<15%。讲"发现问题（profilng）→定位→方案→量化结果"
2. **粘包半包**：为什么TCP是字节流、断帧出现在哪（随机位置）、状态机如何保证任意切割下不丢帧，配边界单测
3. **断线重连的竞态**：QTcpSocket不能跨线程使用，重连逻辑从UI线程移到IO线程（QObject::moveToThread），状态经信号回传UI——Qt多线程的经典考点，讲清"对象所属线程"概念
4. **SQLite写入瓶颈**：逐条insert vs 事务批量 vs WAL模式的三级演进，量化对比
5. **端侧AI推理的工程化**：①模型为什么选1D-CNN而不是更大的（够用+延迟可控+可解释）②推理线程为什么独立（不阻塞接收与UI，异常检测是增值功能不是关键路径）③Python导出与C++推理的数值对齐踩坑（预处理归一化必须两侧一致，误差对齐到1e-5）④端到端延迟X ms如何测出来。这个故事直接回答面试必问题"你怎么看AI对C++岗位的影响"——我的答案：模型是资产，**把它工程化落地的人**是我

## 2. 项目二：mini-log —— 轻量级异步日志库

### 2.1 定位

展示C++语言深度的小型库项目。选日志库的三个理由：①规模可控（单人6周可完成）②技术点密集（并发、内存、格式化、IO全涉及）③业界有成熟参照物（spdlog/Log4j2），压测对比自带说服力。

### 2.2 架构与关键技术点

```
[调用线程] --宏接口(编译期级别过滤)--> [前端: SPSC环/双缓冲] --交换--> [后端线程: 批量格式化+落盘]
                                                        |
                                              [滚动文件管理] [队列满策略] [退出flush]
```

核心技术点及对应的八股考点：

| 技术点 | 关联C++知识 |
|---|---|
| 双缓冲队列（两个缓冲区原子交换） | 为什么不用单队列+锁；交换粒度与延迟的权衡 |
| alignas(64) 规避伪共享 | 缓存行、false sharing的发现与验证 |
| 无锁SPSC环（先做带锁版） | std::atomic、内存序（acquire/release）——两版压测对比即面试故事 |
| 编译期级别过滤宏 | 关闭级别零开销（宏 + 编译期消除） |
| 变参模板 + 格式化 | 完美转发、参数包；先做printf风格保证正确，再演进 |
| RAII文件句柄/单例生命周期 | 退出flush的时机、atexit、与崩溃场景的诚实取舍 |
| 队列满策略（丢弃+计数 vs 阻塞） | 对照Kafka/Log4j2的策略选型，说明为什么默认丢弃 |

### 2.4 面试深挖清单

1. 双缓冲 vs 单队列加锁的取舍（交换O(1)，写放大低）
2. 队列满了丢还是堵？默认丢弃+定期汇总"丢弃N条"，理由是日志库不应反压业务
3. 伪共享：两个热变量落到同一缓存行的现象、perf c2c或时间差验证、alignas(64)修正
4. 崩溃时最后几条日志会不会丢？——信号处理里不能安全加锁，诚实方案：定时fsync+退出flush，说明这是所有异步日志的共性取舍
5. 为什么单线程吞吐能到X万条/秒，瓶颈最后在格式化还是fwrite（用压测数据回答）
