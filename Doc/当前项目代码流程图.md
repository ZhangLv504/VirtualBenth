| 已实现 | 当前工作区存在可执行代码 |

当前代码由三部分组成：

1. **protocol 静态库**：Frame 数据模型、CRC16-Modbus、完整帧编解码、TCP 字节流增量解析。
2. **device_simulator**：Windows/Winsock、单客户端、单次 accept、阻塞式 TCP 服务端。
3. **protocol_tests**：Catch2 协议层单元测试，由 CTest 注册为一个测试目标。

当前没有 host_gui、SQLite、ONNX、DATA 周期推流、多客户端循环、连接超时和重连实现。

需要特别注意：当前工作区正在修改 START/STOP 会话状态，但 process_frame() 仍只真正处理 HELLO；START 和 STOP 仍返回 BAD_STATE。本文会把“实际执行路径”和“协议目标路径”分开绘制。

## 2. 运行时端到端总流程

~~~mermaid
flowchart TD
    START(["启动 device_simulator"])
    MAIN["main() 建立统一异常边界"]
    WSA["构造 WinsockRuntime<br/>WSAStartup 2.2"]

    RECV["recv() 获得任意长度 TCP 字节块"]
    COPY["char 缓冲复制为 vector&lt;uint8_t&gt;"]
    FEED["StreamParser::feed(chunk)"]
    FRAMES{"本次恢复出<br/>0～N 个 Frame"}
    BUSINESS["process_frame(frame)<br/>版本、命令、payload、会话语义"]
    RESPONSE{"需要发送响应？"}
    BUILD["构造 ACK / STATUS / ERROR Frame"]
    ENCODE["ProtocolCodec::encode()"]
    CRC["crc16_modbus()<br/>覆盖 version 到 payload"]
    SEND["send_all()<br/>循环处理部分发送"]
    ACTION{"FrameAction"}
    NEXT["继续处理同批下一帧<br/>或下一次 recv"]
    OK(["run() 返回 true<br/>进程 EXIT_SUCCESS"])
    FAIL(["run() 返回 false<br/>进程 EXIT_FAILURE"])
    EXCEPTION(["捕获 std::exception<br/>打印错误并 EXIT_FAILURE"])
    CLEANUP["作用域退出自动清理<br/>client socket → listen socket → WSACleanup"]

    START --> MAIN --> WSA --> SERVER --> RUN --> LISTEN --> RECV
    RECV -->|bytes_read 大于 0| COPY --> FEED --> FRAMES
    FRAMES -->|0 帧：半包或仅噪声| RECV
    FRAMES -->|1～N 帧，逐帧| BUSINESS --> RESPONSE
    RESPONSE -->|是| BUILD --> ENCODE --> CRC --> SEND --> ACTION
    RESPONSE -->|否| ACTION
    ACTION -->|KeepConnection| NEXT --> FRAMES
    NEXT -->|同批处理完| RECV
    ACTION -->|CloseConnection| OK
    ACTION -->|FatalError| FAIL
    RECV -->|bytes_read 等于 0：对端正常关闭| OK
    RECV -->|SOCKET_ERROR| FAIL
    WSA -. 抛异常 .-> EXCEPTION
    RUN -. 容器等异常 .-> EXCEPTION
    OK --> CLEANUP
    FAIL --> CLEANUP
    EXCEPTION --> CLEANUP
~~~

核心分层不变量：

- recv() 的一次返回不等于一帧；网络层只提供字节块。
- StreamParser 负责缓存、定界、半包、粘包和重同步。
- ProtocolCodec::decode() 只接受“精确一帧”。
- process_frame() 只处理结构和 CRC 已通过的 Frame。
- ProtocolCodec::encode() 只保证通用帧结构，不替业务层校验 ACK、STATUS、ERROR 的 payload 语义。
- send_all() 负责把一帧的全部编码字节提交给 TCP。

当前服务器边界：

- 只绑定 127.0.0.1，不暴露到局域网。
- 只执行一次 accept；连接结束后 run() 返回，进程退出。
- 单线程、阻塞式；没有多客户端、线程池或异步事件循环。

- 没有帧接收 2000ms 超时、TCP keep-alive 配置或断线重连。

~~~mermaid
    P12 -->|否| P14 --> P15
    P15 -->|否：完整帧半包| P7

    P18 -->|否：结构或 CRC 错| P19 --> P3
    P18 -->|是| P20 --> P21 --> P3
~~~

三类输出结果：

- **0 帧**：没有完整 magic、帧头不足、完整帧不足，或输入只有可丢弃噪声。
- **1 帧**：本次恰好补齐一个候选帧。
- **N 帧**：一次 chunk 包含粘连的多帧，成功消费一帧后继续循环。

重同步规则：

- 没有完整 magic 时最多保留最后 1B。
- 非法超长 payload_len 或 decode 失败时只滑动 1B。
- CRC 正确但版本未知或命令未知仍属于完整帧，必须整体消费并交给业务层。

- 不搜索 magic，不保存半包，不拆粘包，不消费外部缓存。

- 结构或 CRC 失败时不发布部分填充的 Frame。

## 9. 当前会话状态代码与协议目标的差异

### 9.1 当前代码实际状态路径

~~~mermaid
stateDiagram-v2
    [*] --> AwaitHello: 静态变量初始化
    AwaitHello --> Ready: HELLO 两帧发送成功后
    Ready --> Ready: 再次 HELLO 成功
    AwaitHello --> AwaitHello: START/STOP 返回 BAD_STATE
    Ready --> Ready: START/STOP 仍返回 BAD_STATE
    Ready --> [*]: 连接关闭或进程退出

    note right of AwaitHello
      send_hello_success 先读取并发送当前状态，
      调用返回成功后才把状态设置为 Ready。
    end note

    note right of Ready
      当前没有 Running 或 Idle 的可执行转换，
      连接结束时也没有显式复位状态。
    end note
~~~

### 9.2 当前未提交状态代码的静态审查结论

| 位置 | 当前事实 | 影响 |
| --- | --- | --- |
| frame.h 的 SessionState | 隐式数值为 AwaitHello=0、Ready=1、Running=2、Idle=3 | 协议 STATUS 定义为 IDLE=0、READY=1、RUNNING=2、FAULT=3；内部状态不能直接无条件转换为线上状态 |
| send_hello_success() | STATUS payload 读取当前 sessionState_ | 初始为 AwaitHello=0，而调用方在两帧发送完成后才改为 Ready，因此当前工作区会先发 0，而不是期望的 READY=1 |
| send_start_success() | 已定义但未调用；ACK 中写的是 Hello | 不能视为 START 已实现 |
| send_stop_success() | 已定义但未调用；ACK 中写的是 Hello | 不能视为 STOP 已实现 |
| process_frame() | START 和 STOP 仍与其他不允许命令一起返回 BAD_STATE | 当前唯一完成的业务成功路径仍是 HELLO |
| sessionState_ 生命周期 | 是类静态变量，连接结束没有显式复位 | 未来加入重复 accept 或复用进程前需要明确每连接状态所有权 |

因此，历史提交中的 HELLO 联调通过证据不能直接覆盖当前未提交修改；当前状态代码应在修正并重新构建、测试、联调后再标记为已验证。

### 9.3 协议规定但尚未实现的目标状态机

~~~mermaid
stateDiagram-v2
    [*] --> AwaitHello: TCP 连接建立
~~~

## 14. 一条完整请求的调用栈示例

以客户端发送合法 HELLO 为例，当前调用关系为：

~~~mermaid
sequenceDiagram
    participant Client as TCP 客户端
    participant Server as TcpServer::run
    participant Parser as StreamParser
    participant Decoder as ProtocolCodec::decode
    participant Biz as process_frame
    participant Encoder as ProtocolCodec::encode
    participant Sender as send_all

    Client->>Server: 任意分块的 HELLO 字节
    Server->>Parser: feed(chunk)
    Parser->>Parser: 缓存、找 magic、按长度定界
    Parser->>Decoder: decode(candidate)
    Decoder->>Decoder: 结构检查 + CRC
    Decoder-->>Parser: Frame(HELLO)
    Parser-->>Server: frames
    Server->>Biz: process_frame(frame)
    Biz->>Encoder: encode(ACK)
    Encoder-->>Biz: ACK 完整字节
    Biz->>Sender: send_all(ACK)
    Sender-->>Client: ACK 字节流
    Biz->>Encoder: encode(STATUS)
    Encoder-->>Biz: STATUS 完整字节
    Biz->>Sender: send_all(STATUS)
    Sender-->>Client: STATUS 字节流
    Biz-->>Server: KeepConnection
    Server->>Server: 继续 recv
~~~

注意：TCP 客户端可能一次收到 ACK 与 STATUS 的粘连字节，也可能分多次收到；客户端仍必须使用同样的流式解析规则恢复帧。
